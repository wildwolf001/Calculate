### P0-2 Model Card（模型卡）契约（2–3d）

**目标**：发布期把 `catalog + profile + semantic + relations` 合成一份结构化、可版本化的模型卡，作为 brief、类型校验、UI 的单一 read model。

**新增文件**：`data/datasets/<id>/model_card.json`（生成物，不手改）。

建议结构（字段级）：

```json
{
  "version": 1,
  "dataset_id": "ds_xxx",
  "semantic_version": 3,
  "data_version": "sha256:...",
  "semantic_fingerprint": "....",
  "tables": {
    "t_006": {
      "label": "order_reviews",
      "role": "dimension",
      "rows": 9232,
      "grain": ["c01"],
      "primary_key": ["c01"],
      "time": "c06",
      "description": "",
      "columns": [
        {"name":"c01","label":"review_id","type":"varchar","role":"pk","pii":false},
        {"name":"c02","label":"order_id","type":"varchar","role":"fk","fk":"t_003.c01"},
        {"name":"c03","label":"review_score","type":"integer","role":"measure",
         "unit":"score","min":1,"max":5,"top_values":[3,5,4,1,2],"description":"1-5 分"}
      ]
    }
  },
  "relations": [{"from":"t_006.c02","to":"t_003.c01","card":"N:1"}],
  "metrics": [
    {"id":"m_llm_平均评分","name":"平均评分","type":"aggregate",
     "aggregation":"avg","operand":"t_006.c03","expr":"AVG(t_006.c03)",
     "fact":"t_006","scope":{"t_003.c03":"delivered"},"time_via":"t_006.c06",
     "unit":"分","synonyms":["评分","平均分"],"definition":"..."}
  ],
  "dimensions": [
    {"id":"d_doc_t_003_c07_c08","name":"是否延迟","kind":"derived",
     "expr":"t_003.c07 > t_003.c08","labels":{"true":"延迟","false":"准时"}}
  ],
  "time_axes": [{"ref":"t_006.c06","name":"评价时间","coverage":["2024-01-08","2026-01-07"]}],
  "value_policy": {"inline_values_per_dim": 5, "full_values_file": "dim_values.json"}
}
```

工作项：

1. 定义 Pydantic/dataclass `ModelCard`（或 JSON Schema + 校验函数），放在 `app/datasets/model_card.py`。
2. 生成器 `build_model_card(ctx)`：
   - 表：来自 catalog/profile（label、rows、grain、time）；
   - 列：合并 catalog（type/samples/pii）+ profile（unit/min/max/top_values）+ `TableInfo.role`（需要持久化，见 3）；
   - 关系：来自 `sem.relations`/joins；
   - 指标：从语义层补充 `aggregation`/`operand`（需要从 expr 解析或新增字段，见 3）；
   - 维度/时间轴：来自 semantic.yaml。
3. 持久化列角色与单位：
   - 在 `catalog.json` 的 column 增加 `role`、`unit`、`description`（可选）；
   - 或在 `semantic.yaml` 的 tables 下增加 `column_meta`，但推荐放 catalog/model_card，避免污染业务口径；
   - `generic_pipeline` 写入时从 `TableInfo` 复制 `role/unit`（目前只算不存）。
4. 发布链路：`publish.py` 在写 YAML/index 后生成 `model_card.json`，写入 `semantic_version` 与指纹；`load_context` 加载；`index` 可从 model card 派生（先并存，逐步切换）。
5. 校验：`model_card.validate()` 检查表/列引用、主键存在、FK 对应关系、指标 operand 存在；发布失败则回滚。
6. 测试：unit（合成小库）、integration（发布后文件存在、字段正确）、context 加载。

**验收**：

- `model_card.json` 中 `t_006.c03.role == "measure"`、`unit == "score"`、`min/max` 正确；
- `m_llm_平均评分.operand == "t_006.c03"`（若新增该指标）；
- 任一指标 `aggregation in {avg,sum}` 时 operand 必为数值列，否则 validate 报错；
- 模型卡与 `semantic_version`/指纹一致，draft 编辑后失效/重建。

### P0-3 Brief v2：schema 优先、相关表选择、分段预算（2d）

**目标**：让“列名/类型/主外键/粒度”永远先于低价值重复出现，并且按问题只选相关表。

**新结构（固定顺序）**：

```text
[dataset] id / semantic_version / 覆盖时间 / 表数
[metrics] top-k(≤8): id|name|type|expr|fact|time_via|unit|scope     ~800
[dimensions] top-k(≤8): id|name|column|labels|matched values(≤5)     ~700
[schema] 相关表（≤6 张）：
  t_006 label=order_reviews rows=9232 grain=(review_id) time=review_created_at

    c02 order_id      FK→t_003.c01 varchar
    c03 review_score      integer  min=1 max=5

[docs] top-k(≤3): 定义/公式                                             ~300
```

工作项：

### P0-4 派生指标类型闸门 + 修复策略（1.5–2d）

**目标**：即使 brief 仍缺列，也绝不让 `AVG(varchar)` 进入执行；失败要可解释、可纠正。

工作项：

1. **类型校验**（`app/domain/query/metric.py` 或 model card 校验）：
   - `aggregation in {SUM, AVG}`：operand 必须数值（integer/decimal/float）；
   - `COUNT/COUNT_DISTINCT`：任意列；
   - 失败报结构化错误：`AVG 需要数值列，t_006.c02 是 varchar；同表数值列：c03(review_score)`；
   - parser 捕获后：带错误重试 1 次（把候选列写进错误），仍失败转澄清。
2. **错误分类**（`recovery.py`）：
   - 先识别 `avg(varchar)/no function matches` → `TYPE_MISMATCH`，不要归 `UNSUPPORTED_PLAN`；
   - 文案：“评分列类型不对”，而不是“维度组合无法解析”。
3. **修复候选**：
   - 类型错误时**不**尝试 `drop_comparison/widen_time`；
   - 允许一个确定性修复：若同表存在唯一数值列且标签与问题词匹配（如 review_score），替换 operand；
   - 否则直接澄清/拒答，并给出候选列。
4. **发布期探针**：publish 对每个指标执行一次 `prepare + execute`，类型错误直接阻断发布（readiness block）。
5. **测试**：`AVG(varchar)`、`SUM(varchar)`、跨表 operand、COUNT 正常列、修复成功/失败路径。

**验收**：EC51E4 T8 最大代价变成“一次澄清”或“自动换列成功”，不再出现 SQL binder 错误后连试 3 次的拒答。
